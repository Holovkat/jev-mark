# Requirements handoff packet (version 1)

Run `python3 <jev-mark>/scripts/requirements_readiness.py --packet <private.json> --output <private-result.json> --cwd <project-root>`.

The example is structural, not live evidence. All example paths/quotes/IDs must be replaced. CLI reads complete files and live tracker bodies; no arbitrary shell commands or URLs are accepted. Tracker calls are read-only argument-array `glab api` or `gh api` invocations.

- `tracker`: `provider` is `gitlab` or `github`, `project` is namespace/repository, `scope.id` is numeric. `scope.kind` is `milestone`, GitLab group `epic` (requires `tracker.group`), or `issue_children` for project issue epics. The latter inventories all Markdown checkbox lines containing `#IID` or same-project issue/work-item URLs in the live parent. Ordinary prose references are excluded. No child checklist or ambiguous/unavailable evidence abstains; supplied tasks must equal the whole inventory. Multi-project group epic inventories are unsupported and abstain. Parent title/body is semantic evidence.
- `documents`, `policies`: arrays of local file paths, relative to `--cwd` or absolute. Policies must include the currently applicable authoritative sources. Ancestor `AGENTS.md` files are added automatically. `.secure` sources are prohibited. Other sources must be secret-free; outbound evidence and output use shared credential redaction.
- `discussion`: stable `id`, `state` (`agreed`, `brainstorm`, `superseded`), full meaningful verbatim `quote`, `source` local file. A private transcript excerpt assembled by the orchestrator is acceptable; retain original turn/message references in that file. Quotes must occur in readback. Agreed rows require requirement links; other states do not create scope.
- `requirements`: stable `id`, verbatim documented `text`, `source` belonging to `documents`, `decision_ids`, `task_ids`, `scenario_ids`. References must resolve. Optional `deferral: {quote, source}` requires verbatim owner agreement; JEV determines whether the evidence actually authorizes deferral. No undocumented/model-created exemption.
- `tasks`: numeric tracker issue `id`, `kind` (`implementation`, `verification`), `requirement_ids`, `scenario_ids`. One verification task must have `after` containing every implementation task ID and `before_dev_uat: true`; it covers every scenario. Multiple scenario cases/suites inside that one task are allowed. Live ticket bodies must confirm these commitments; declarations alone cannot approve them. Mandatory per-implementation micro-test gates violate the shared cadence.
- `scenarios`: stable `id`, `text`, `requirement_ids`, `implementation_task_ids`. Links between requirements, tasks and scenarios must be bidirectional.

The output contains `gate` (`PASS`, `FAIL`, `ABSTAIN`), `verification_topology` (`PASS`, `FAIL`) plus `single_verification` (`PASS`, `FAIL`) requiring both topology and an accounted semantic verification-ticket row, an evidence `matrix` (discussion, requirement, verification-contract and overall inventory rows), finite coverage decisions (`accounted`, `partial`, `missing`, `ambiguous`, `deferred`, `abstain`), sanitized errors, gateway coverage-field evidence metadata, elapsed time, and evidence fingerprint. Missing links/topology fail deterministically. Missing/unavailable evidence, outages and malformed/partial responses cannot pass. Overall inventory judgment checks requirements absent from supplied rows against live scope evidence. This does not automatically discover the entire conversation: discussion completeness remains the orchestrator's responsibility.

Output replacement is atomic and mode 0600. Reuse requires unchanged packet, whole live source contents, policy contents and tracker inventory/bodies; live readback is always repeated. A matching semantic cache additionally requires a fresh valid finite gateway availability decision; outage cannot return a cached PASS. Capacity follows gateway contracts (16 MiB body, 64 contexts, 180-second request timeout), batches without truncation; an oversized single context abstains. CLI success exit code is 0 only for PASS. No provider/model selector is exposed.
